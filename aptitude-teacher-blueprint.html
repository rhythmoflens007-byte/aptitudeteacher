01

Scope — what "v1" actually includes

"Build it in one go" means: no mid-build re-planning, not "every feature launches simultaneously." The list below is what ships in the single v1 build, in the order Section 07 lays out. One item is deliberately deferred, with a free substitute standing in for it.

Auth + profile Question bank (3 sections, 5 difficulty levels) Practice / Quiz / Mock test modes Instant answers + step-by-step explanations AI doubt-solving chat (text) Voice in/out (browser-native) OCR from photographed questions AI-generated practice questions Adaptive difficulty + misconception detection Personalized daily path Mastery dashboard, streaks, XP, badges Multilingual UI + tutor responses 2D animated avatar (illustrated, viseme-synced) Photoreal video avatar (HeyGen/Tavus)
Why the avatar is swapped, not cut Every vendor that does photorealistic lip-synced video (HeyGen, Tavus, D-ID, Soul Machines) bills per minute — none has a free tier that survives real usage. Section 02 substitutes a self-built 2D illustrated tutor whose mouth shape follows live audio amplitude. It delivers the "face that talks back" requirement at $0. Swap in a vendor later once there's revenue to fund it — nothing else in the build depends on which one you use.

04

The adaptive engine — the actual differentiator

Everything above is standard ed-tech plumbing. This is the loop that makes it more than a quiz app: diagnose the gap, teach to it, retest it, move on only when it's closed.

1 · Tag everything at the skill level, not just the topic level

Every question maps to one topic (Quant / Logical / Verbal) → subtopic (e.g. "Time & Work") → one or more fine-grained skills (e.g. "converting rate-to-time", "combined-work LCM shortcut"). Mastery is tracked per skill, not per subtopic — a student can be strong at the formula and weak at the LCM shortcut inside the same subtopic.

2 · Classify every wrong answer by why it's wrong

On an incorrect attempt, send the question, the correct method, and the student's working (typed or transcribed) to Gemini with a fixed classification prompt. It returns one of:

Misconception typeSignalMastery penalty
careless_slipCorrect method, arithmetic errorSmall
conceptual_gapWrong method entirelyLarge
partial_methodRight approach, stopped short / misapplied a stepMedium
no_attemptSkipped or guessedMedium, flagged for a worked example first

3 · Update mastery, weighted by that classification

Each skill carries a 0–100 mastery_score. A correct answer raises it by an amount scaled to question difficulty (harder-than-current-level correct answers move it more). A wrong answer lowers it by an amount scaled to the misconception type above — a conceptual_gap drops mastery hard and re-queues the skill sooner than a careless_slip does.

4 · Teach before retesting

When conceptual_gap or partial_method is detected, the tutor doesn't just show the correct answer — it generates a short targeted micro-lesson for that specific skill, then queues a fresh, AI-generated question on the same skill (never the same question) for later in the same session.

5 · Pick the next question by weakest-skill-due

The practice feed always pulls from: skills with the lowest mastery among those "due" (attempted recently enough to still be top-of-mind, spaced-repetition style), at a difficulty band matched to current mastery — never max difficulty on a skill still near zero.

6 · Daily goal = personalized, not generic

Each day's goal auto-composes from: a fixed number of questions on the 2–3 lowest-mastery skills, plus one reinforcement question on a skill mastered in the last 3 days (to prevent regression). This is the "personalized learning path" requirement — it's this rule, not a separate feature.

06

API surface

Grouped by module, in the order they get built (Section 07). Auth routes are handled by Supabase directly from the client and aren't listed.

Questions & practice

GET/questions/nextReturns the next question per the adaptive rule (Section 04.5). Query: topic_id optional.
POST/attemptsSubmit an answer. Triggers misconception classification + mastery update.
GET/questions/{id}/explanationStep-by-step explanation, generated on first request and cached.
POST/questions/generateAI-generates a fresh question for a given skill + difficulty (used by the "teach then retest" flow).

Quiz & mock test

POST/quizzesStart a timed quiz: body specifies topic mix + question count.
POST/quizzes/{id}/submitSubmit all answers at once; returns score + per-question breakdown.
GET/mocks/{id}/reportFull mock-test report: section-wise score, time spent, weak skills surfaced.

AI tutor (text + voice + OCR)

POST/tutor/sessionsOpen a tutor session, optionally linked to a question_id.
POST/tutor/sessions/{id}/messagesSend a message (text or transcribed voice); returns the tutor's reply.
POST/tutor/ocrUpload a photographed question; returns the transcribed question text + auto-opens a tutor session on it.

Progress & gamification

GET/progress/masteryPer-skill mastery scores for the dashboard.
GET/progress/daily-goalToday's generated goal + completion state.
GET/gamification/summaryXP, level, streak, earned badges.
07

Build workflow

Strict dependency order — each phase needs the state or plumbing the previous one created. This is the order to actually write code in, whether that's one continuous session or spread across days.

  1. 00

    Infra bootstrap

    Create the Supabase project, Upstash Redis instance, Gemini API key, and repo (frontend + backend as a monorepo, see Section 08). Wire environment variables end to end before writing any feature code.

  2. 01

    Auth + profile

    Supabase Auth (email/password + Google), a users row on sign-up, and a bare profile page.

    unlocks → everything else, since every table hangs off user_id
  3. 02

    Question bank + seed content

    Build the topics/subtopics/skills/questions tables and an admin seed script. Seed ~150–200 real questions across all three sections before moving on — the practice engine has nothing to serve without this.

  4. 03

    Practice engine

    GET /questions/next (unweighted/random for now), POST /attempts, instant correct/incorrect + static explanation display.

    unlocks → quiz mode, mastery engine
  5. 04

    Quiz & mock test modes

    Timed sessions, scoring, section-wise mock report.

  6. 05

    Adaptive + misconception engine

    Wire the Gemini classification call into POST /attempts, add skill_mastery updates, switch /questions/next from random to weakest-skill-due (Section 04).

    unlocks → the actual differentiator
  7. 06

    AI doubt-solving tutor (text)

    Chat UI + /tutor/sessions + /tutor/messages, backed by Gemini with the question's context injected into the prompt.

  8. 07

    OCR

    Image upload to Supabase Storage → Gemini vision transcription → auto-opens a tutor session on the parsed question.

  9. 08

    Voice

    Web Speech API wired into the tutor chat: mic button → SpeechRecognition → text message; tutor reply → SpeechSynthesis.

  10. 09

    Avatar

    2D illustrated character with 4–6 mouth-shape frames swapped based on live TTS audio amplitude. Purely cosmetic layer on top of Phase 08 — no new data flows.

  11. 10

    Gamification

    gamification + daily_goals tables, XP/streak/badge logic, dashboard UI.

  12. 11

    Multilingual

    Locale field on users, prompt templates parameterized by language, SpeechSynthesis voice selection by locale.

  13. 12

    Polish + PWA + deploy

    Installable manifest/icons, empty/loading/error states, deploy per Section 10.

10

Deployment

Frontend

Vercel

Connect the repo, deploy /apps/web. Free Hobby tier — 100 GB bandwidth/month.

Backend

Render / Fly.io

Deploy /apps/api as a free web service. Free tier sleeps after inactivity — acceptable pre-launch, upgrade once there's steady traffic.

Database

Supabase

Same project used in development — just point production env vars at it, or spin up a second free project for prod isolation.

Cache

Upstash

Serverless — no separate deploy step, just a production token.

Risks to watch

Latency stacking in the voice loop STT → Gemini round-trip → TTS → avatar can feel sluggish if each step is naive. Stream the Gemini response and start TTS on the first sentence rather than waiting for the full reply.
Free-tier backend cold starts Render/Fly's free tier sleeping mid-demo reads as "broken app" to a first-time user. Add a lightweight keep-alive ping if you're demoing live, or accept the ~10–30s wake delay pre-launch.
Gemini free-quota ceiling Fine for a prototype and a small cohort; a real user base will hit the daily cap. The Ollama fallback in Section 02 is the release valve — don't build it until quota pressure is real.
